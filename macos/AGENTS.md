# macos/ — unshipped desktop target

Flutter-generated scaffolding. **This target is not shipped**: the product
ships Android, iOS and Web (see [docs/ARCHITECTURE.md](../docs/ARCHITECTURE.md)).
Nothing here is exercised by CI, the release process, or the test suite.

## Treat it as generated

`flutter/generated_plugin_registrant.*` and `generated_plugins.cmake` are
regenerated by `flutter pub get`. They will show up as modified in
`git status` after almost any tooling run, usually with **no content change**
— just an mtime touch that git's stat cache reports until the index is
refreshed:

```bash
git update-index --refresh   # then re-check: usually a clean diff
```

Don't commit that churn, and don't hand-edit those files.

## If you ever do ship this target

Several features are mobile-only and would need real implementations or
explicit no-ops: home-screen widgets (`home_widget`), background fetch,
local notifications, and the Android quick-settings tile. The conditional
imports in `lib/controller/` (`widgets_mobile.dart` / `widgets_other.dart`,
`screenshots_mobile.dart` / `screenshots_other.dart`) are split on
`dart.library.io` vs `dart.library.js`, so a desktop build currently takes
the `io` branch — i.e. the **mobile** path — which is not obviously correct
for desktop. Check that before assuming a desktop build behaves.
